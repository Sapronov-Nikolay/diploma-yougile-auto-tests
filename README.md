# Дипломная работа: Автоматизация тестирования YouGile
### 📎 Сделано на основе предыдущей работы. Ссылка на финальный проект (ручное тестирование)

## 📌 Описание проекта

Автоматизация UI- и API-тестов для системы управления проектами **YouGile**.  
Проект основан на курсовой работе по ручному тестированию (Postman-коллекция, тест-план).

**Создайте и активируйте виртуальное окружение (чтобы не тащить мусор из глобалки):**

- Создание среды (Работает даже в понедельник или четверг 😉😅): `python -m venv venv`
- Вход в среду для Linux/macOS: `source venv/bin/activate`
- Вход в среду для Windows: `venv\Scripts\activate`

**Автоматизированные сценарии:**

### 🖥️ UI-тесты (7 шт)
1. **Успешная авторизация** – вход с валидными данными.
2. **Авторизация с неверным паролем** – проверка сообщения об ошибке.
3. **Создание проекта** – через интерфейс, после проверки проект удаляется через API (уборка за собой).
4. **Создание доски** – внутри проекта (проект открывается из уже существующих, при отсутствии — создаётся автоматически).
5. **Создание колонки** – на доске (проект и доска создаются в рамках теста).
6. **Создание задачи** – в колонке (проект, доска, колонка создаются в рамках теста).
7. **Уборка тестовых проектов** – удаляет через UI все проекты, созданные автотестами за прошлые прогоны (по маске имени).

### ⚙️ API-тесты (6 шт)
1. **Получение CompanyId** – POST `/api-v2/auth/companies`.
2. **Получение API-ключа** – POST `/api-v2/auth/keys`.
3. **Создание проекта (позитивный)** – POST `/api-v2/projects`.
4. **Получение проекта по ID** – GET `/api-v2/projects/{id}`.
5. **Обновление проекта** – PUT `/api-v2/projects/{id}`.
6. **Мягкое удаление проекта** – PUT `/api-v2/projects/{id}` с `deleted: true`.

## 🧠 Логика взаимодействия UI-тестов

Чтобы не путаться, как тесты работают друг с другом, ниже описана схема.

- **UI-03** создаёт проект через UI, находит его ID в левой панели и **сразу удаляет через API** — так тест проверяет полный цикл (создание + чистая уборка за собой) и не оставляет мусор.
- **UI-04, UI-05, UI-06** — каждому из них нужен **любой существующий проект**. Они открывают первый попавшийся на странице `/team/`. Если проектов нет (например, UI-03 удалил свой) — автоматически создаётся временный проект с именем `NNNN_Auto_Project` и работа идёт в нём.
- **UI-07** — финальный уборщик. Собирает по маске `NNNN_Test_Project_UI` и `NNNN_Auto_Project` все тестовые проекты, оставшиеся на `/team/`, и удаляет их через UI. Чужие проекты не трогаются — фильтр по регулярному выражению.

**Почему именно так:** каждый тест самодостаточен. Если запустить `UI-05` в одиночку — он не упадёт, а создаст себе проект. Если запустить `UI-07` в одиночку — он подчистит всё, что найдёт, или ничего не сделает, если убирать нечего.

## 🗂 Структура проекта

Для просмотра полной структуры проекта используйте файл **`tree.txt`** – он содержит дерево всех файлов и папок.

Основные директории:
Проект построен по принципу разделения ответственности:
- **`src/api/`** – API-клиент и эндпоинты.
- **`src/ui/`** – Page Object и локаторы.
- **`tests/`** – тесты, размеченные Allure-аннотациями.
- **`src/ui/locators.py`** – все локаторы в одном словаре (используются `data-testid`).
- **`config.py`** – настройки из `.env`.

### 🔑 Управление API-ключами (критически важно!)
**YouGile ограничивает количество активных ключей до 30.
Без очистки тесты могут упасть с ошибкой 429 (Too Many Requests).
Для управления ключами используйте `key_manager.py` (команды выше).
Рекомендуется запускать `--clean` перед каждым большим прогоном тестов. Таким как цикличный прогон по 15 - 20 раз.**

- Просмотр всех API-ключей: `python key_manager.py --list`
- Очистка старых API-ключей: `python key_manager.py --clean`
- Очистка с сохранением указанного ключа: `python key_manager.py --clean --keep <ключ>`

### 🧹 Очистка данных
- В проекте есть два уровня уборки за собой — чтобы репозиторий и аккаунт не зарастали мусором при цикличных прогонах.

1. Уборка в момент создания (UI-03).
- Тест создаёт проект через UI, находит его ID в левой панели, и сразу удаляет его через API.
- Так проект не висит в компании, а в Allure видно отдельный шаг «Удалить проект через API».

2. Уборка накопленного (UI-07).
- Тест собирает через UI все проекты, попадающие под маску автотестов (`NNNN_Test_Project_UI` и `NNNN_Auto_Project`),
- и удаляет их через интерфейс (три точки → «Удалить» → подтверждение).
- Чужие проекты не трогаются — фильтр строго по регулярному выражению.

3. Уборка API-проектов (autouse-фикстура в API-тестах).
- После каждого API-теста созданный проект мягко удаляется (`deleted: true`) через `soft_delete`.
- Проект уходит в архив, из активного списка исчезает.
